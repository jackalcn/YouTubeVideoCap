# YouTube影片下載平台

貼上 YouTube 影片、Shorts、播放清單或頻道連結，選擇畫質後下載影片、音訊與字幕。在自己的電腦上執行時，也能下載 Vimeo、Bilibili、Facebook、Instagram、X、TikTok 等其他網站的影片，以及直接的影片網址（見「[其他網站的影片](#其他網站的影片)」）。以 [Streamlit](https://streamlit.io) 和 [yt-dlp](https://github.com/yt-dlp/yt-dlp) 建置。

請僅下載你擁有權利或已獲授權的內容（例如自己上傳的影片、Creative Commons 授權內容），並遵守 YouTube 與各網站的服務條款，以及當地著作權法。

## 功能

| 頁面 | 可以做什麼 |
| --- | --- |
| **下載** | 貼連結或整段文字（自動找出其中的連結；影片 ID 和 @頻道代號要自己一行，可用空格或逗號分隔），或匯入清單檔。解析後可以預覽格式、大小與檔名，也能看字幕、章節、說明和匯出留言。播放清單和頻道可以勾選要下載的影片、匯出影片清單 CSV，也能排程在指定時間開始。在自己的電腦上，其他網站的連結和直接的影片網址也照同樣的流程，解析結果會標明是哪個網站 |
| **佇列** | 任務在背景執行，切換頁面或關閉分頁都不會中斷。可暫停、續傳、取消、重試、調整順序與同時下載數，完成時可跳出桌面通知。可以設定下載時段；遇到 YouTube 限制會自動暫停再續跑，網路中斷會自動重試。App 重新啟動後，未完成的任務會接著做 |
| **搜尋** | 在 App 裡搜尋 YouTube，勾選後下載 |
| **媒體庫** | 瀏覽下載資料夾、依檔名搜尋、預覽影音與字幕、在單一字幕檔裡搜尋文字、開啟或刪除檔案（字幕、封面等附加檔一起刪，刪除會移到回收桶），以及清除未完成的暫存檔。下載紀錄裡有的檔案會標明來自哪個網站 |
| **訂閱** | 追蹤頻道或播放清單，定時下載新影片。可以編輯、從 Google Takeout 或 OPML 匯入，也可以設定保留規則，自動刪除舊影片 |
| **歷史** | 搜尋下載紀錄（含來源網站）、重新下載、匯出 CSV |
| **工具** | 剪輯、轉成 H.264、壓縮、抽音訊、嵌入或燒錄字幕（可調字體大小、位置、背景與字型）、擷取畫面、音量標準化（-16 或 -23 LUFS）、合併多段影片（不同格式也能接，統一轉成 H.264）、轉成 GIF（最長 60 秒）。沒有字幕的影片可以用語音辨識產生字幕。字幕可以轉換格式、轉成台灣繁體，或合併成雙語字幕。有支援的顯示卡時可以加速轉檔 |
| **系統** | 檢查相依工具、更新 yt-dlp、檢查 App 新版本、選用安裝（語音辨識、模擬瀏覽器）、自己通過網站的真人驗證、測試連線、匯出匯入設定、備份與還原、通知、開機自動啟動 |

下載時可以設定：

- **影片**：畫質上限、編碼（H.264／VP9／AV1）、容器（MP4／MKV／WebM）、HDR、指定格式 ID、配音語言
- **音訊**：M4A、MP3、Opus、FLAC、WAV 或不轉檔，可設定位元率與封面。開啟「音樂標籤」時，會從標題整理出歌手與歌名，並把封面裁成正方形
- **字幕**：語言、格式、自動產生的字幕、嵌入影片、整理成純文字逐字稿。簡體字幕可以自動多存一份台灣繁體（含台灣用語）
- **片段與章節**：
  - 只下載指定時間或勾選的章節，或移除指定時間
  - 依章節分割，存進以影片命名的資料夾
  - 嵌入章節
  - 用 [SponsorBlock](https://sponsor.ajay.app) 標記或移除業配、自我宣傳、提醒訂閱等片段，章節名稱用中文
- **播放清單與頻道**：
  - 每個播放清單／頻道預設下載前 20 部，可在左側調整，本機最多 200 部；解析後的勾選清單最多列 500 部
  - 影片網址帶有 `list=` 參數時，預設只下載那一部影片
  - 勾選要下載的影片
  - 從清單尾端開始
  - 依片長、日期、觀看數、標題或授權篩選
  - 略過 Shorts 和已下載過的影片
- **直播**：錄製進行中的直播，隨時可以停止並保留已錄到的內容；等待還沒開始的直播（最多 24 小時）；另存直播聊天室紀錄
- **附加檔**：封面（可轉成 JPG）、影片資訊、說明、留言（CSV）、給 Kodi／Jellyfin／Plex 用的 .nfo。MKV 可以把影片資訊嵌入檔案
- **輸出**：
  - 檔名規則：不同影片同名時，會自動在檔名加上 `[影片 ID]`，不會互相覆蓋
  - 資料夾：依頻道或日期分，或使用媒體伺服器（Plex／Jellyfin）的資料夾格式
  - 自訂 yt-dlp 範本
  - 把檔案時間改成上傳日期
  - 優先使用繁體中文的標題與說明
- **網路**：限速、代理伺服器、影片之間的等待時間、YouTube 用戶端、只用 IPv4
- **進階**：直接加上 yt-dlp 的命令列參數

使用預設的 YouTube 用戶端時，若 YouTube 拒絕下載（HTTP 403），App 會自動改用 ios_producer 和 web_embedded 用戶端再試一次（ios_producer 不能登入，所以登入時只用 web_embedded；yt-dlp 2026.11.23 以前的版本沒有 ios_producer，也只用 web_embedded）；自己選了用戶端時不會更換。常用組合可以存成預設，也內建了音樂、Podcast、學習筆記等組合；在自己的電腦上，組合還可以一併記住下載資料夾，套用時直接切換。下載頁會顯示下載資料夾所在磁碟的剩餘空間，剩不到 2 GB 時仍可下載，但會提醒可能不夠。

## 在本機執行

需要 Python 3.11 以上和 [ffmpeg](https://ffmpeg.org)。沒有 ffmpeg 仍可下載，但畫質通常只有 360p，也無法轉成 MP3、剪輯片段或嵌入字幕。Windows 可以用 `winget install Gyan.FFmpeg` 安裝。

最簡單的方式：Windows 雙擊 `start.bat`；macOS 和 Linux 執行 `sh start.sh`。

- 第一次執行會自動安裝，之後直接開啟。
- 安裝中斷、Python 換了版本，或資料夾被移動時，再執行一次就會自動修好。
- 放在網路磁碟機上也能執行。

這兩個腳本預設只讓這台電腦連線；要開放給區網其他裝置，先設定環境變數 `VIDEOCAP_ADDRESS=0.0.0.0`，那些裝置會以受限權限連線（見下方「誰能做什麼」）。

也可以手動執行：

```
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m videocap --server.address localhost
```

macOS 和 Linux 請把路徑換成 `.venv/bin/python`。`python -m videocap` 會先啟動下載引擎，再啟動網頁伺服器；後面可以接任何 Streamlit 選項，例如 `--server.port 8600` 換埠號。手動執行時不會自動開瀏覽器，請自己開 http://localhost:8501（或加上 `--server.headless false`）。少了 `--server.address localhost`，Streamlit 會讓區網裡的所有裝置都連得到。`start.bat` 和 `start.sh` 後面也可以接同樣的選項。

### 開機自動啟動（Windows）

到「系統」頁開啟「開機自動啟動」，或執行 `autostart.bat`（取消：`autostart.bat remove`）。之後每次登入 Windows，App 會在背景啟動，不開視窗，直接用瀏覽器開 http://localhost:8501 即可。訂閱和排程下載要 App 在執行才會進行，所以常用訂閱的話建議開啟。

- 背景執行的這一份只接受本機連線，不受 `VIDEOCAP_ADDRESS` 影響。
- App 的路徑太長（超過 259 個字元）或含有 `%` 時，Windows 的捷徑會指到錯的地方，App 會拒絕建立並說明原因；請把 App 移到較短、沒有 `%` 的路徑。

背景執行的 App 要重新啟動時（例如更新 yt-dlp 之後），請登出 Windows 再登入，或在工作管理員結束 `pythonw.exe` 後執行 `start.bat`。

### 更新 yt-dlp

YouTube 常改版。如果下載開始失敗，先到「系統」頁按「檢查新版本」，有新版時再按「更新 yt-dlp」，或手動執行：

```
.venv\Scripts\python.exe -m pip install -U "yt-dlp[default,deno]"
```

yt-dlp 需要 [Deno](https://deno.com) 才能取得完整的畫質選項，上面的指令會一併安裝。App 偵測不到 Deno 時，會在左側提示，到「系統」頁按「安裝 Deno」即可。

已經安裝[模擬瀏覽器](#模擬瀏覽器選用)時，「更新 yt-dlp」會一併確認 curl-cffi 的版本和新的 yt-dlp 相容，不相容就換成相容的版本，不會把它移除。手動更新時，請把指令裡的 `yt-dlp[default,deno]` 改成 `yt-dlp[default,deno,curl-cffi]`。

### 更新 App

「系統」頁的「檢查 App 新版本」會向 GitHub 查詢；按過一次後，之後每天開系統頁時會自動再查。有新版時請重新下載 zip 或執行 `git pull`，再執行 `start.bat`（macOS／Linux 是 `start.sh`）。用 zip 下載、沒有 git 的版本只能用日期大略比對。

## 下載會員影片

用 App 左側的「會員登入」登入已加入會員的 YouTube 帳號，就能下載該頻道的會員專屬影片。YouTube 不開放第三方用帳號密碼登入，所以有兩種方式：

- **使用瀏覽器的登入狀態**：先在瀏覽器登入 YouTube，再於 App 選擇該瀏覽器。只在本機以 `localhost` 開啟時提供。Windows 上的 Chrome、Edge 常因加密或檔案鎖定而讀不到，建議使用 Firefox。
- **上傳 cookies.txt**：照 App 內「如何匯出 cookies.txt」的步驟匯出後上傳。

選好後可以按「確認登入狀態」先檢查。要下載整個頻道的會員影片，可以貼會員專屬清單：把頻道 ID 開頭的 `UC` 換成 `UUMO`，例如 `https://www.youtube.com/playlist?list=UUMOxxxxxxxx`。

請僅下載你已有權限且獲授權保存的內容。yt-dlp 官方提醒，帳號搭配 yt-dlp 使用有被暫時或永久封鎖的風險，請控制下載量。登入時任務會逐一執行，每部影片之間間隔 5–10 秒。

## 其他網站的影片

在自己的電腦上執行時（以 `localhost` 開啟），「下載」頁也接受 YouTube 以外的連結：

- **yt-dlp 支援的網站**：Vimeo、Bilibili、Facebook、Instagram、X（Twitter）、TikTok、Twitch、Dailymotion、Internet Archive 等，完整清單見 [yt-dlp 支援的網站](https://github.com/yt-dlp/yt-dlp/blob/master/supportedsites.md)。
- **直接的影片網址**：`.mp4`、`.webm`、`.m3u8` 等影音檔或串流清單。
- **一般網頁**：yt-dlp 會在網頁裡找播放器（例如 `<video>`），找得到就能下載。

流程和 YouTube 一樣：貼連結、解析、預覽格式、大小與檔名，再加入佇列。解析結果會標明是哪個網站，「歷史」和「媒體庫」也看得到。

- **連結怎麼認**：其他網站的連結要帶 `http://` 或 `https://`。貼整段文字時，影片網站和直接的影片網址會直接加入；其餘的一般網頁如果和別的連結混在一起，會先擱置，勾選「也嘗試這 N 個一般網頁」才加入（文章裡順帶提到的網頁通常不是影片）。網址後面直接接中文或全形標點時，網址到那裡為止。
- **網址參數**：只去掉 `utm_` 開頭、`fbclid`、`gclid`、`igshid` 這類追蹤參數，其餘原樣保留，帶簽章的網址才不會失效。
- **照常適用的設定**：畫質上限、音訊轉檔、字幕（網站有提供時）、片段與章節、檔名規則、下載資料夾、附加檔、限速、代理伺服器、略過已下載過的影片。
- **播放清單**：只要 yt-dlp 列得出來，就能照樣勾選。其他網站的清單是依「第幾部」下載勾選的影片，清單在下載前有變動時，可能會下載到別部。
- **只對 YouTube 有效的功能**：SponsorBlock、YouTube 用戶端與 HTTP 403 自動重試、搜尋、訂閱、錄製直播與等待開播、直播聊天室紀錄、另存留言、會員專屬清單。對其他網站的連結開著這些設定不會出錯，App 會略過，並用一句話說明這個網站不支援。
- **需要登入的網站**：沿用左側的「會員登入」。上傳的 `cookies.txt` 要包含那個網站的登入資料；選瀏覽器時，App 會讀取該瀏覽器的登入狀態，下載時把各網站自己的登入資料送給那個網站。「確認登入狀態」只檢查 YouTube。
- **影片 ID**：直接的影片網址和一般網頁沒有影片 ID，App 用「檔名加上網址的短雜湊」當 ID（例如 `clip-3f9a1c2e`）。所以兩個網站各自的 `clip.mp4` 是兩部影片：檔案不會互相覆蓋，「略過已下載過的影片」也分得開；同一個網址再下載一次，才會被認成同一部。
- **沒有副檔名的直接網址**：網址和伺服器都沒說明檔案類型時，App 會先讀檔案開頭的一小段來判斷（MP4、WebM、MKV、MP3 等），存成對應的副檔名。
- **有 DRM 保護的服務**（Netflix、Disney+ 等）無法下載，App 會直接說明，不會嘗試繞過。
- **串流要看來源網頁**：有些網站只讓「從它自己的網頁連過去」的請求拿到影片串流（`.m3u8` 的清單和片段），直接貼串流網址會收到 HTTP 403，訊息也會提示這一點。在「進階 yt-dlp 參數」填 `--referer 影片所在網頁的網址` 就能過關。要填的是網頁的網址，不是串流網址：填成串流網址，網站會拒絕，側邊欄也會提醒。這個值會送給每個連結的每個請求，所以只在貼串流網址時才需要；App 找得到網頁裡的串流時，會自己帶正確的來源網頁。「解析連結」和「開始下載」都會套用這一行：解析連結只套用影響連線的選項（標頭、`--extractor-args`、代理、逾時、略過憑證檢查、地區繞過、請求間隔），所以填了 `--write-info-json` 這類會存檔的選項，解析連結也不會存任何東西。
- **網頁讀得到、串流被拒絕**：貼的是網頁，而這次被拒絕（HTTP 403）的全是串流或影片檔（網址看得出是 `.m3u8`、`.mp4` 這類）時，訊息會直接說被擋下的是串流、不是網頁，並列出拒絕它的主機。yt-dlp 的原文這時可能寫著「Unable to download webpage」，指的其實是那個串流網址。只有串流的分段被拒絕時不在此列：解析會成功，下載才失敗。第一段就被拒絕時，下載以 yt-dlp 的原文（例如「The downloaded file is empty」）失敗；第一段拿得到、後面的分段連續 10 段下載失敗時，App 會停止這部影片，說明是串流的分段下載失敗，並引用最後一次的錯誤（例如 HTTP 403），不會一段段略過到最後（一部長片可能有幾千段）。失敗是因為網路斷線時，照「網路中斷自動重試」處理。
- **播放器腳本壓縮過的網頁**：有些網頁把串流網址藏在壓縮過的（packed）播放器腳本裡，網頁文字裡找不到 `.m3u8`，yt-dlp 會說網頁裡沒有影片。這時 App 會再讀一次網頁，把腳本還原（只是依對照表換字，不會執行網頁的任何腳本），找出 `.m3u8` 清單的網址，再照網頁播放器的方式連線：以這個網頁當來源網頁（網址在別的網站時，只送網頁所在的網站和 Origin，和瀏覽器一樣），然後解析和下載。標題、縮圖和 ID 都取自網頁，「解析連結」看到的和下載的是同一部。每個網頁最多試 3 個網址。
- **播放器放在內嵌網頁（iframe）裡的網頁**：另一些網頁把播放器放進 `<iframe>`，有時 iframe 裡還有一層 iframe。yt-dlp 只會跟進它認得的播放器，其他的 iframe 不會打開，所以說網頁裡沒有影片；有時它反而找到網頁上寫給搜尋引擎看、其實下載不了的網址，這時訊息說的是串流被拒絕（見上面「網頁讀得到、串流被拒絕」）。遇到這兩種情況，而且網頁自己的壓縮腳本裡也沒有串流時，App 會跟進 iframe：
  - **順序**：對每個 iframe，先把它的網址交給 yt-dlp（它可能是 yt-dlp 認得的播放器，或是有 `<video>` 的網頁）；yt-dlp 找不到，才讀那個內嵌網頁的文字，找壓縮腳本裡或直接寫出來的 `.m3u8` 網址；還是沒有，再對它裡面的 iframe 做同樣的事。前一步成功，就不會再讀後面的網頁。
  - **先試哪一個**：網頁上的廣告和計數器也是 iframe，常常排在播放器前面。App 先試看起來像播放器的：可以全螢幕或自動播放的、宣告的尺寸像播放器的、網址裡有 `embed`、`player` 或 `video` 的；隱藏的排最後；寬或高只有 0 或 1 像素的略過。iframe 的網址寫在 `data-src` 這類延遲載入的屬性裡也讀得到。
  - **來源網頁**：讀內嵌網頁時，以內嵌它的那個網頁當來源網頁（Referer）；抓串流時，以真正放播放器的那個內嵌網頁當 Referer 和 Origin。同一個網站送完整網址，別的網站只送所在的網站，和瀏覽器一樣。內嵌網頁有轉址時，以實際到達的網址為準。
  - **名字**：結果記在你貼的那個網頁名下，標題、縮圖和 ID 都取自它。解析結果和下載備註會用一句話說明影片取自哪個內嵌網頁（顯示網域），工作紀錄會列出試過哪些。例外是內嵌的播放器屬於 YouTube 或 yt-dlp 有專用支援的網站（例如 Vimeo）時：標題、縮圖和 ID 用那個網站自己的，和直接貼那個網站的連結一樣。內嵌的 YouTube 影片完全照直接貼 YouTube 連結的方式處理，不帶你貼的網頁的任何標頭。
  - **上限**：每個網頁跟進 2 個 iframe，最多 2 層；一次最多讀 6 個內嵌網頁、試 8 個候選。App 自己讀網頁最多 30 秒；連同 yt-dlp 試候選的時間超過 90 秒，就不再試新的，並說明已經試過哪些。下載時按「停止」，搜尋也會停下來。
  - **真人驗證與模擬瀏覽器**：內嵌網頁或串流所在的網站要求真人驗證時，訊息會寫出是哪個網站，「開啟瀏覽器視窗，自己通過驗證」也開到那個網站，通過後再試就會沿用。內嵌網頁的網站只讓瀏覽器連線時，App 會改用模擬瀏覽器再讀一次（已安裝時）。
  - **不會跟到這台電腦或內部網路**：公開網頁裡的 iframe 或串流網址指向這台電腦或內部網路時，App 不會跟進。`localhost`、`192.168.x.x` 這類位址算，寫成 `127.1`、`0x7f.0.0.1` 這類少見的形式也算；沒有設定代理伺服器時，名稱解析出來是內部網路的位址也算。你貼的網頁本身就在這台電腦或內部網路時，不受這個限制。

  只有本機擁有者的連結才會這樣做，訪客和公開主機不會跟進任何 iframe。App 只讀網頁的文字，不執行網頁的腳本，也不開瀏覽器去載入網頁。「進階 yt-dlp 參數」的 `--referer` 優先於 App 自己帶的來源網頁；因此被網站拒絕時，訊息會提醒可以把那一行拿掉。

公開主機與區網訪客維持只能下載 YouTube：其他網站的連結等於讓執行 App 的那台主機去連任意網址，包含它所在內部網路的位址，所以只開放給本機擁有者，進階 yt-dlp 參數也改不了這個限制。

### 模擬瀏覽器（選用）

有些網站（多半由 Cloudflare 把關）只讓瀏覽器連線，一般的程式會收到 HTTP 403，yt-dlp 的訊息是「Cloudflare anti-bot challenge」。yt-dlp 可以用 [curl-cffi](https://github.com/lexiforest/curl_cffi) 套件，照瀏覽器的方式連線來通過這類檢查。這是選用功能，只有在自己電腦上執行的擁有者看得到，線上版沒有安裝。

- **安裝**：到「系統」頁的「模擬瀏覽器」按「安裝模擬瀏覽器（下載不到 10 MB）」，裝好不必重新啟動。版本由 pip 依目前安裝的 yt-dlp 決定（yt-dlp 2026.10.26 會裝 curl-cffi 0.17）。
- **什麼時候用到**：其他網站的連結被拒絕（HTTP 403），而且什麼都還沒下載到時，App 會把整個連結改用瀏覽器的連線方式再試一次，只試這一次，解析和下載都一樣。影片網頁、直接的影片網址、串流清單（m3u8）和它的每個片段，在這次重試裡都照瀏覽器的方式連線。成功時，結果會註明用了模擬瀏覽器。
- **只用在 YouTube 以外的網站**：YouTube 的解析、下載和字幕都不經過它，和沒有安裝時完全一樣。其他網站的網頁內嵌 YouTube 影片時，送往 YouTube 的請求也照原本的方式連線。進階 yt-dlp 參數的 `--impersonate` 會被忽略；`--extractor-args "generic:impersonate"` 仍然可以自己填。
- **過不了的情況**：模擬之後網站仍然要求真人驗證（例如勾選「我不是機器人」）時，App 不會代為通過驗證，會說明並停止；你可以自己通過，見下一節。模擬之後仍是單純的拒絕時，顯示原本的 HTTP 403 說明（可能要登入、連結已過期，或網站不允許下載）；被拒絕的只有網頁帶出來的串流或影片檔時，改用上面「網頁讀得到、串流被拒絕」的說明。
- **停用與移除**：「系統」頁可以隨時按「停用模擬瀏覽器」或「移除模擬瀏覽器」。在 Windows，執行中的 App 已經載入套件時，檔案刪不掉，所以 App 會先停用；重新啟動後再按一次「移除模擬瀏覽器」即可。
- **自我檢查**：把它和 YouTube 隔開的做法用到 yt-dlp 的內部結構，yt-dlp 更新後可能改變。所以 App 啟動時，以及安裝或啟用之後，都會檢查一般的 yt-dlp 連線是不是真的找不到模擬瀏覽器。檢查沒過時 App 照常能用，但會自動停用模擬瀏覽器，並在「系統」頁和左側提醒重新啟動；重新啟動之後，yt-dlp 就完全找不到這個套件。
- **Docker**：在容器裡同樣用「系統」頁的按鈕安裝，套件存在 `/data`，重建容器也會保留。

### 自己通過真人驗證

網站要求真人驗證時（錯誤訊息是「要求真人驗證」），App 不會代為通過，但你可以自己通過，再讓 App 沿用：

1. 按失敗訊息下方的「開啟瀏覽器視窗，自己通過驗證」。也可以先到「系統」頁的「網站驗證」輸入網址再開。
2. App 用這台電腦上的 Chrome、Edge 或 Brave（依序找第一個），開一個設定檔全新的視窗到那個網頁，你在裡面通過驗證（例如勾選「我不是機器人」）。Cloudflare 的驗證通過後，App 會自動偵測，視窗也會自動關閉；別家的驗證留下的 cookie 不一樣，通過後請在 App 按「我已通過驗證」。
3. 再試一次：失敗的下載工作底下有「用通過的驗證重試」；解析連結失敗時，再按一次「解析連結（不下載）」或「開始下載」。

- **不是你貼的那個網站時**：要求驗證的可能是網頁內嵌的播放器，或串流所在的另一個網站。訊息會寫出是哪個網站，視窗也開到那裡（要求驗證的是串流網址時，開到那個網站的首頁）；通過的是那個網站的驗證，之後再試你原本貼的連結即可。
- **App 拿走什麼**：視窗裡那個網站的 cookies，和瀏覽器怎麼介紹自己（User-Agent 與 Sec-Ch-Ua 標頭）。之後對那個網站的請求，都帶同樣的 cookies、用同樣的介紹，模擬瀏覽器也換成最接近那個版本的 Chrome，網站才認得這是通過驗證的那個瀏覽器。自己填的 `--user-agent` 優先於瀏覽器的介紹。其他網站的 cookies 一律不留；視窗的設定檔是暫時的，用完就刪，不會讀你平常瀏覽器的任何資料。
- **存多久**：只存在記憶體，關閉 App 就清掉。另存的 `.info.json` 和嵌入 MKV 的影片資訊都不含 cookies，登入的 cookies 也一樣。「系統」頁的「網站驗證」列出已通過的網站和通過的時間，可以個別清除。網站會在自己設定的時間後讓通過的驗證失效（常見是 30 分鐘左右，和 cookie 上寫的期限無關），失效時會再出現同樣的錯誤，再通過一次即可。
- **用 cookies.txt 登入時**：yt-dlp 結束時會把它手上的 cookies 存回 cookie 檔，所以通過驗證的 cookies 也會寫進 App 放在暫存資料夾的那份 cookies.txt 副本。副本在工作結束時刪除，下載失敗或取消也一樣；你上傳的檔案不會被改。
- **代理伺服器**：側邊欄設定了代理伺服器時，視窗也走同一個代理（帳號密碼不放進指令列，需要時由瀏覽器自己詢問）。通過驗證的憑證和網站看到的 IP 綁在一起，視窗和之後的請求要從同一個位址出去。
- **誰能用**：視窗開在執行 App 的這台電腦的螢幕上，所以只有本機擁有者、在這台電腦前操作時才有這個功能；公開主機和區網訪客沒有。YouTube 的連結不會用到它。
- **找不到瀏覽器時**：App 會說明。可以用環境變數 `VIDEOCAP_BROWSER` 指定瀏覽器程式的路徑。Firefox 和 Safari 不能用，它們的偵錯連線是另一種；Linux 沒有桌面畫面時也不能用。
- **不一定通過**：網站可以要求比 cookies 和瀏覽器介紹更多的條件。通過了仍被擋住時，App 會照原本的錯誤說明，不會再試別的辦法。

## 訂閱

在「訂閱」頁加入頻道或播放清單，App 會依設定的間隔檢查並下載新影片。加入時可以選「只追蹤之後的新影片」，不下載以前的影片。

- **編輯**：可以改名稱、檢查間隔、每次最多下載幾部、下載資料夾，或改用左側目前的下載設定。
- **匯入**：在 [Google Takeout](https://takeout.google.com) 只勾選 YouTube，匯出後找到 `subscriptions.csv` 上傳；也接受其他 App 匯出的 OPML。
- **保留規則**：可以只保留最新幾部，或刪除下載超過幾天的影片。只會刪這個訂閱自己下載、而且還在它資料夾裡的檔案，連同字幕等附加檔；刪掉的影片不會再被下載。

訂閱要 App 在執行才會檢查：保持 `start.bat` 開著、開啟「開機自動啟動」，或用 Docker 執行。

## 下載時段與自動處理

這些都只作用在自己電腦上的下載，公開主機訪客的任務不受影響：

- **下載時段**：在「佇列」頁設定，例如 02:00–07:00（可以跨午夜），用這台電腦的時間。時段外，排隊的下載和訂閱的自動檢查會等到時段開始才進行，正在下載的不會中斷，檔案工具也照常執行。預設關閉。
- **遇到 YouTube 限制自動暫停**：下載因為 HTTP 429 或「要求驗證」失敗時，整個佇列暫停 15 分鐘再自動繼續，避免帳號或 IP 被封得更久；有設定通知的話會收到一則訊息。按「立即繼續」或「全部繼續」可以提早結束；手動暫停的任務不會被喚醒；重新啟動 App 會清掉這個暫停。
- **網路中斷自動重試**：下載因為連線中斷失敗時，會在 2、5、10 分鐘後各自動重試一次，保留已下載的部分；按「重試」可以馬上再試。用上傳的 cookies.txt 登入的任務不會自動重試，因為任務停止後登入資料就不在了。

## 語音辨識字幕

沒有字幕的影片或音訊，可以用 [Whisper](https://github.com/openai/whisper)（faster-whisper）自動產生字幕。這是選用功能，只有在自己電腦上執行的擁有者看得到。

- **安裝**：到「系統」頁的「語音辨識」按「安裝語音辨識（下載約 125 MB）」，裝好不必重新啟動；也可以手動執行 `.venv\Scripts\python.exe -m pip install -r requirements-speech.txt`。
- **使用**：在「工具」頁選好影片或音訊，打開「語音辨識」分頁，選模型和語言後開始。字幕存成 SRT 放在原檔旁邊，例如 `影片.zh-TW.srt`；已有同名字幕時存成 `影片.zh-TW-ai.srt`，不會覆蓋。結果會列在「工具結果」，也會跟影片一起出現在「媒體庫」。
- **模型**：tiny（約 75 MB）、base（約 145 MB）、small（約 480 MB，只用處理器時建議）、medium（約 1.5 GB）、large-v3（約 3 GB）、large-v3-turbo（約 1.6 GB，準確度接近 large-v3 但快好幾倍，有顯示卡時建議）。越大越準，也越慢。每個模型第一次使用時會從 Hugging Face 下載到資料資料夾的 `models/whisper`（預設 `~/.youtube-videocap/models/whisper`），之後離線也能用；「系統」頁會列出已下載的模型。
- **語言**：自動偵測、中文、英文、日文、韓文。Whisper 常把中文寫成簡體字，預設會用 OpenCC 轉成台灣繁體和用語，夾在中文字之間的半形標點也會改成「，。？！」。選的語言和聽到的不同時，完成時會提醒。
- **速度**：只用處理器時，tiny 大約是即時的 9 倍（96 秒的語音約 11 秒）；1 小時的影片用 small 約需 20–40 分鐘，medium 可能和影片一樣長。
- **顯示卡**：有 NVIDIA 顯示卡時，「系統」頁會多出「顯示卡支援」的狀態，按「安裝顯示卡支援（下載約 650 MB）」裝好 cuBLAS 程式庫即可，不必另外裝 CUDA 或 cuDNN，裝好不必重新啟動（驅動程式要夠新）。之後「工具」頁的「使用顯示卡」會自動勾選。在 2016 年的 GTX 1050 Ti 上，tiny 模型處理 96 秒語音只要約 3.4 秒，模型越大差距越大。缺少程式庫時會自動改用處理器完成並提醒。
- **Docker**：在容器裡同樣用「系統」頁的按鈕安裝，套件和模型都存在 `/data`，重建容器也會保留。

## 刪除檔案

媒體庫的刪除和訂閱的保留規則，在 Windows 的本機硬碟、macOS 和 Linux 桌面上會把檔案移到回收桶，可以還原；網路磁碟、隨身碟、NAS、Docker 和伺服器沒有回收桶，會永久刪除，刪除前會先說明是哪一種。回收桶裡的檔案仍然佔用空間，保留規則是為了省空間的話，記得清空回收桶。「清除暫存檔」一律永久刪除。Windows 關閉了回收桶或檔案太大裝不下時，Windows 會直接永久刪除。

## 通知

在「系統」頁的「通知」填入 Discord Webhook 網址、Telegram Bot Token 與 Chat ID，或 [ntfy](https://ntfy.sh) 主題網址，下載完成或失敗、訂閱有新影片或檢查失敗時就會收到訊息。同一批下載只會發一則。存好的網址和 Token 不會再顯示在頁面上，也不會寫進備份。

只要瀏覽器開著 App，也可以在「佇列」頁開啟「完成時通知我」，任務完成時跳出桌面通知。瀏覽器只在 `localhost` 或 https 網址允許桌面通知，用區網 IP 或 Docker 的 http 網址開啟時不會有。

## 備份與還原

「系統」頁的「備份與還原」可以把訂閱、下載紀錄、預設組合、設定與下載紀錄檔打包成一個 zip，換電腦時再還原。備份不含通知的網址與 Token、代理伺服器的帳號密碼，以及進階 yt-dlp 參數裡的登入資料；還原時會保留這台電腦原本的這些設定。有任務在執行時不能還原。只還原你自己建立的備份：還原會帶回備份裡的所有設定，包括進階 yt-dlp 參數。

「匯入下載紀錄檔」可以匯入 yt-dlp 的 `--download-archive` 紀錄檔，之後這些影片會被當成已下載過而略過。

上傳的檔案最大 10 MB。備份檔超過時，可以用 `.venv\Scripts\python.exe -m videocap --server.address localhost --server.maxUploadSize 200` 啟動後再還原。

## 用 Docker 執行

適合放在家用伺服器或 NAS。檔案存在 `downloads/`，設定與紀錄存在 Docker volume。

```
docker compose up -d
```

- 容器一啟動就會開始檢查訂閱、接續未完成的任務，不必先開網頁。
- 預設只有這台電腦連得到（`http://localhost:8501`）。要讓其他裝置連線，請在 `docker-compose.yml`：
  - 拿掉 `127.0.0.1:`；
  - 設定 `VIDEOCAP_PASSWORD`；
  - 在 `VIDEOCAP_ALLOWED_HOSTS` 列出那些裝置在瀏覽器輸入的位址或名稱，例如 `192.168.1.20,nas.local`。

  沒列出的名稱只能用一般訪客的權限。
- 時區預設是 `Asia/Taipei`（`TZ`），用在伺服器端產生的時間，例如等待開播時顯示的預定時間。排程下載和頁面上的時間依瀏覽器所在的時區計算。
- 下載的檔案屬於 `downloads` 資料夾的擁有者；Docker 自動建立資料夾時是 uid 1000。要指定 NAS 帳號，請設定 `PUID` 和 `PGID`（用 `id` 指令查詢）。
- 映像檔已內建中文字型，燒錄的中文字幕不會變成方框。
- 在「系統」頁更新 yt-dlp 後，執行 `docker compose restart` 重新啟動。更新存在資料 volume 裡，`docker compose up -d` 重建容器也會保留；重新建置映像檔時會裝最新版。
- 容器先以 root 啟動，調整好資料夾權限後才切換成 `app` 使用者。在容器裡手動執行指令時，請加上 `-u app`，例如 `docker compose exec -u app videocap python -m pip list`，以免產生 root 擁有的檔案。

## 部署

線上版本：https://youtube-videocap.streamlit.app/

推送到 `main` 分支後，Streamlit Community Cloud 會自動部署；系統套件列在 `packages.txt`。

YouTube 常限制雲端主機的 IP。實測在 Streamlit Community Cloud 上，解析連結正常，但多數影片下載會被回 HTTP 403，所以要穩定下載請在本機執行。

也可以試著在 App 的「會員登入」上傳 `cookies.txt`，但這個做法尚未實測。cookies 等同登入憑證，請只上傳到你信任的部署環境。

### 誰能做什麼

App 會依連線來源決定權限，避免公開網址的訪客碰到主機：

| | 本機（localhost） | 公開主機或區網訪客 |
| --- | --- | --- |
| 下載到 | 自己選的資料夾 | 伺服器暫存，約兩小時後刪除，只能用瀏覽器存回去 |
| 可以下載的網站 | YouTube、yt-dlp 支援的其他網站、直接的影片網址 | 只有 YouTube。其他網站的連結會讓伺服器去連任意網址，所以不開放 |
| 任務 | 所有分頁共用 | 只看得到自己的。同時 1 項（同一個網路位址共用）；排隊時每人最多 5 項、同一個網路位址最多 10 項，整台主機最多 20 項。單項最長 30 分鐘，關閉頁面約 5 分鐘後自動取消 |
| 媒體庫、訂閱、歷史、檔案工具、詳細紀錄、備份、通知設定 | 有 | 無 |
| 代理伺服器、自訂範本、進階 yt-dlp 參數、選擇下載資料夾與資料夾分類（依頻道、播放清單、日期或媒體伺服器）、精準剪切、略過已下載過的影片、更新 yt-dlp、模擬瀏覽器、自己通過網站的真人驗證、錄製直播、等待開播、聊天室紀錄、.nfo、讀取瀏覽器登入 | 有 | 無 |
| 標題篩選、字幕語言 | 可用正規表示式 | 只接受一般文字與語言代碼 |
| 一次解析的連結數／每部影片之間等待 | 100 個／最多 3600 秒 | 10 個／最多 10 秒 |
| 每個播放清單／頻道最多下載 | 200 部 | 20 部 |
| 另存留言 | 最多 100,000 則 | 最多 500 則 |
| 單檔／單次任務上限 | 無 | 1 GB／2 GB，伺服器上同時最多保留 3 GB 的完成檔案 |
| 清除自己的資料 | — | 「佇列」頁的「清除我的資料」會刪除自己的任務、暫存檔與上傳的 cookies |

存回電腦時要按兩次：先按「下載」準備檔案，再按「存到電腦」。多個檔案可以打包成 zip，但合計不能超過 50 MB；更大的請逐一下載。頁面上的時間都以瀏覽器所在的時區顯示。

App 透過 `localhost` 連線來判斷「本機」。如果在同一台電腦上用 nginx 等反向代理對外開放，代理必須帶上 `X-Forwarded-For` 標頭（nginx 的常見寫法是 `proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;`），否則所有訪客看起來都像本機。保險起見，也可以直接設定 `VIDEOCAP_MODE=cloud` 和密碼。

### 存取密碼

設定 `VIDEOCAP_PASSWORD`，或在 `.streamlit/secrets.toml` 寫入 `app_password = "你的密碼"`，開啟 App 時就要先輸入密碼。

- `secrets.toml` 請存成 UTF-8（Windows 11 記事本的預設格式，含 BOM 也可以）。存成 UTF-16 或 Big5 時，App 會在啟動時停下來並說明原因；內容格式錯誤時，App 會保持鎖定。
- 同一個網路位址連續輸錯 5 次後，要等 30 秒才能再試，之後每次加倍，最長 5 分鐘。

### 環境變數

| 變數 | 用途 |
| --- | --- |
| `VIDEOCAP_PASSWORD` | 開啟存取密碼，見上方「存取密碼」 |
| `VIDEOCAP_MODE` | `local` 或 `cloud`，強制指定模式，取代自動偵測 |
| `VIDEOCAP_TRUST_REMOTE` | 設為 `1` 時把遠端連線視為本機擁有者，用於 Docker 等私人環境。請同時設定密碼和 `VIDEOCAP_ALLOWED_HOSTS` |
| `VIDEOCAP_ALLOWED_HOSTS` | 搭配 `VIDEOCAP_TRUST_REMOTE`：除了 localhost，還信任哪些網址名稱，以逗號分隔。可以防止其他網站冒充這台主機 |
| `VIDEOCAP_OUTPUT_DIR` | 預設下載資料夾，預設是 App 資料夾裡的 `downloads` |
| `VIDEOCAP_DATA_DIR` | 紀錄與設定的位置，預設是家目錄下的 `.youtube-videocap` |
| `VIDEOCAP_ADDRESS` | `start.bat`／`start.sh` 監聽的位址，預設 `localhost` |
| `VIDEOCAP_HEADLESS` | `start.bat`／`start.sh` 設為 `true` 時不自動開瀏覽器 |

### 從影片網頁直接送過來

在網址加上 `?url=連結` 會把連結填入下載頁，但不會自動開始。「工具」頁有現成的書籤小工具，在 YouTube 或其他網站的影片頁點一下就能送到 App；其他網站的連結一樣只有本機擁有者能下載。

手機也可以：在 iOS 的「捷徑」App 建立一個「開啟 URL」的捷徑，網址填 `http://電腦的位址:8501/?url=` 接上「捷徑輸入」，再從 YouTube App 的分享選單選它；Android 可用任何能把分享連結接到網址後面的工具。手機要連得到這台電腦（區網要設定 `VIDEOCAP_ADDRESS=0.0.0.0`，或用 Docker），而且會以訪客權限使用，所以只能送 YouTube 的連結。

## 已知限制

- 下載片段時，yt-dlp 透過 ffmpeg 處理，過程中沒有進度百分比，取消也要等這一段處理完。
- 搜尋結果只有相關性排序。YouTube 的日期排序參數實測沒有作用，所以不提供。
- 續傳靠 yt-dlp 的 `.part` 檔；YouTube 的下載網址有時效，暫停太久可能要重新解析，App 會自動處理。
- 直播錄製從按下開始的時間點起算，無法回溯到直播開頭。
- 用瀏覽器存回電腦的單一檔案最大 2 GB；更大的檔案請直接到下載資料夾取用。
- 同一個資料與設定資料夾（預設是家目錄下的 `.youtube-videocap`，或 `VIDEOCAP_DATA_DIR`）只能有一個 App 在管理。開了第二個時，它不會檢查訂閱或接續任務，「系統」和「訂閱」頁會提示。
- 訪客直接開啟擁有者專用的網址（例如 `/library`）時，會回到下載頁，但 Streamlit 會先跳出英文的「Page not found」提示；這是 Streamlit 內建的訊息，無法改成中文。同樣無法改成中文的還有上傳框的「Upload」、「2MB per file」等字樣，以及排程日期的月曆。
- YouTube 拒絕 `tv` 和 `tv_downgraded` 用戶端（「必須重新載入頁面」，2026 年 11 月用 yt-dlp 2026.11.23 實測），所以「YouTube 用戶端」和自動重試都不再用它們，之前存的這兩個設定會改回「預設」。
- 從 yt-dlp 2026.11.23 起，`web_embedded` 只有 HLS 格式（和 360p 以下的 18 號格式）不需要 PO token，其他格式拿不到，可選的格式比較少。`ios_producer` 只有 H.264 和 AAC 格式，不能登入，要 yt-dlp 2026.11.23 以上才會出現在清單裡。

其他網站：

- 有 DRM 保護的內容（Netflix、Disney+ 等串流服務）無法下載，App 不會嘗試繞過。
- 部分網站要登入才能下載，請用「會員登入」。實測 Vimeo 目前連公開影片也要登入；Facebook、Instagram、X、Bilibili 的部分影片或高畫質也常要登入。
- 部分網站只讓瀏覽器連線。在「系統」頁安裝[模擬瀏覽器](#模擬瀏覽器選用)後，這類網站回 HTTP 403 時，App 會改用瀏覽器的連線方式再試一次。仍然過不了的有兩種：要求真人驗證的網站，App 不會代為通過驗證，要[自己在瀏覽器視窗裡通過](#自己通過真人驗證)；yt-dlp 交給 ffmpeg 自己抓取的串流（例如直播，和少數 yt-dlp 不能自己下載的 HLS），ffmpeg 的連線不會模擬。
- 模擬瀏覽器只在一個真實的 Cloudflare 網站上實測過：它有時直接放行，有時要求真人驗證，自己通過驗證之後，解析連結成功（整部影片的下載沒有試）。其他網站能不能通過，要試了才知道；其餘都是用本機的測試網站（模擬 Cloudflare 的 HTTP 403 和驗證頁）驗證的。
- 驗證視窗只實測過 Cloudflare 的驗證。別家的驗證留下的 cookies 不同，視窗不會自動偵測，要自己按「我已通過驗證」，沒有實測過。
- 驗證視窗需要 websockets 15 以上，但 yt-dlp 只要求 13 以上。很久沒更新的環境請先執行 `python -m pip install -U websockets`，否則視窗會顯示「沒有順利開啟」。
- 通過驗證的網站裡內嵌了 YouTube 影片時，同一次下載裡送往 YouTube 的請求也會帶那個瀏覽器的 User-Agent 和 Sec-Ch-Ua 標頭。cookies 不會送到 YouTube，連線方式也不會模擬；直接貼 YouTube 的連結不受影響。
- yt-dlp 把下載交給 ffmpeg 時（例如只下載片段，或少數 yt-dlp 不能自己下載的 HLS），cookies 會放在 ffmpeg 的指令列參數裡，這台電腦上的其他程式看得到。登入的 cookies 也一樣，這是 yt-dlp 的做法。
- 沒有安裝模擬瀏覽器時，只有 yt-dlp 明說是 Cloudflare 檢查的失敗會提示安裝。網頁本身讀得到、只有串流清單或影片檔被拒絕時，訊息會說被擋下的是串流，但看不出安裝後有沒有幫助，所以不提示安裝；只有串流的分段被拒絕時也不提示：第一段就被拒絕時只顯示 yt-dlp 的原文，後面的分段連續被拒絕時說明是串流的分段下載失敗。
- 從網頁腳本或內嵌網頁找串流，只處理寫在文字裡的 HLS（`.m3u8`）網址：壓縮過的（packed）腳本裡的，或內嵌網頁裡直接寫出來的。網址要先執行腳本、解密，或要先呼叫網站的 API 才組得出來時，App 找不到；請從瀏覽器的開發人員工具複製串流網址貼上，需要時再填 `--referer`。你貼的網頁裡沒壓縮的網址由 yt-dlp 自己找，App 不重複處理。
- 內嵌網頁（iframe）只認寫在網頁原始碼裡的。由腳本在瀏覽器裡才插入的 iframe，和用 `srcdoc` 把整份文件寫在屬性裡的 iframe，App 找不到。先試哪個 iframe 是依它的屬性和網址猜的：播放器沒有任何像播放器的特徵，又排在兩個以上的其他 iframe 後面時，可能輪不到它。
- 「不跟進這台電腦或內部網路」的判斷有範圍。只管 App 自己從網頁裡挑出來的網址：iframe、腳本裡的串流，和交給 yt-dlp 的候選。交給 yt-dlp 之後，它自己跟的轉址、串流清單裡列的分段網址、它在網頁裡找到的內嵌，都和你直接貼任何網頁連結時一樣，不在這個判斷之內。內嵌網頁轉址到內部網路時，App 是讀完才發現，然後丟掉內容不用，請求已經送出去了：yt-dlp 的連線沒有在轉址前停下來的開關。名稱解析的檢查擋不住 DNS 重新綁定（檢查時回公開位址、連線時回內部位址）；有代理伺服器時不做這項檢查，因為名稱是代理那一端解析的。
- 內嵌網頁裡再內嵌 YouTube 影片，由 yt-dlp 在同一次執行裡自己跟過去時，送往 YouTube 的請求會帶著 App 為那個內嵌網頁算出來的 Referer。cookies 不會送到 YouTube，連線方式也不會模擬；App 自己在網頁裡看到的 YouTube iframe 不受影響。
- 其他網站的直播、搜尋、訂閱和另存留言還不支援；貼直播連結會顯示「目前只支援錄製 YouTube 直播」。
- 網站只提供單一檔案時，會依「輸出容器」挑檔案。選 MP4（預設）：網站有 MP4 就拿 MP4，即使另一種格式的解析度比較高；沒有 MP4 時保留網站提供的格式（例如 `.ogv`、`.flv`），不會轉檔，需要時可以到「工具」頁轉成 H.264。選 WebM：有 WebM 就拿 WebM，沒有就裝進 MKV。選 MKV：拿解析度最高的，再裝進 MKV。網站在影音合一的檔案之外還提供純音訊檔時，仍然拿解析度最高的那個檔案。
- 帶時效簽章的直接影片網址，簽章換了就會被當成另一部影片。這類網址會原樣存進下載紀錄，匯出或分享紀錄前請留意。
- 各網站的錯誤訊息很多，常見的幾類（不支援的網址、需要登入、地區限制、HTTP 403／404、DRM）有中文說明，其餘顯示 yt-dlp 的原文。

## 開發

```
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest
.venv\Scripts\python.exe -m pytest -m network
.venv\Scripts\python.exe -m pytest -m browser
.venv\Scripts\python.exe -m ruff check .
```

`pytest` 不連網，約 1,900 項測試、5–10 分鐘，用真正的 yt-dlp 和 ffmpeg 處理本機的假 YouTube 資料。`pytest -m browser` 會開一個真的 Chrome、Edge 或 Brave（不開視窗），測試驗證視窗讀得到瀏覽器的 cookies；平常的測試用一個假的瀏覽器程式代替。`pytest -m network` 會真的連到 YouTube：約下載 15 次一部 19 秒的影片和一次 4 分鐘的音樂影片，也會搜尋、列出頻道並查詢 SponsorBlock，太常執行可能被 YouTube 暫時限制。最後幾項會連到其他網站：從 Internet Archive 下載一部 1 分鐘的影片，從 MDN 下載一個 5 秒的 `.mp4`；只想跑這幾項可以用 `-k` 指定，例如 `pytest -m network -k "another_site or elsewhere or direct_link"`。其他網站的離線測試會在本機開一個小型 HTTP 伺服器，提供影片檔、含 `<video>` 的網頁和 m3u8。

程式放在 `videocap/`：下載引擎與佇列不依賴 Streamlit，介面都在 `videocap/ui/`，`main.py` 只是 Streamlit 的進入點，`python -m videocap` 是啟動器。GitHub Actions 會在 Linux 和 Windows 上跑測試並建置 Docker 映像檔，也會在 macOS 上做基本檢查。
